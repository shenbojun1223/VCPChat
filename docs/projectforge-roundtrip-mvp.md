基线 e385a4f95391c500b784e3534b188f4cac63427a；

## 唯一用户路径

A 正常施工、自动发布、退出交权 → B 自动接续并施工、发布、交权 →
A 启动识别落后，安全更新原目录、原本地工程，再通过正常 Forge 继续施工。
复用一个固定 Hub、现有网络/映射/租约/宿主入口，不另造同步平台。

## 更新前置条件

- 仅显式启用的映射工程；固定 globalId、本地 projectId、接收库、映射库与绝对目录。
- 自动更新前写门关闭且无在途 Worker/Forge 操作；有效租约在写盘前重新确认。
- 用上次已确认 revision 的完整可信 bundle 作基线，比较本地登记字节、项目元数据、
  Todo、批次/节点、已结束 Capture。只忽略跨设备重映射的主键，不忽略内容或署名/时间。
- 拒绝未发布本地改动、外部字节漂移、未结束 Capture、尚未解决的发布请求、
  身份/目录/授权漂移及不同历史分支。不做合并，不使用 force 自动覆盖。
- 远端新文件若撞上本地未登记文件，即使内容相同也拒绝；保留未登记文件与目录。
- 新版本须包含基线既有履历，不因全局 ID 相同就允许替换为另一条历史。
- 原本地工程 ID、根目录及既有历史节点 ID 保留；远端新记录只映射新增 ID。

## 更新与恢复

仅改动登记文件，不交换整个目录，不碰 .git、依赖或配置。
写盘前持久保存固定旧/新 bundle、更新身份与恢复信息；更新中普通读写均不可用，
跨进程重开也拒绝误读半更新工程。文件/业务库/映射不共同原子，不伪称一次大事务。
逐步恢复必须检查原目录身份和文件状态；遇未知内容保留证据并停止，不盲目补写或回滚。
接收库记录、文件与本地映射完成对账后才恢复可见；再次核验租约才放行正常写入。
旧 schema 进程须停止，测试只对临时库启用新扩展；不直接迁移常驻业务库。

## 必须验收

1. 真实 HTTP 的正常 Forge A→B→A，再A→B；各端 projectId/root不变、履历/Todo/字节一致。
2. 文件编辑、新建、删除/移动、中文/BOM/CRLF/二进制；原历史节点可继续GUI查看/回退。
3. 本地代码/Todo/履历/open Capture、未登记目标碰撞均拒绝，字节不被覆盖。
4. SQL失败与真实进程退出后，同一更新恢复不多建工程、不重复历史、不冒报ready。
5. 失租/授权收回/目录替换拒绝；旧Forge功能回归；冻结源码指纹、TAP与退出码一起核实。

## 不在本轮范围

不重开上一轮Caddy路由/Hub或验收客户端，不启用业务工程同步；
真实跨设备部署另行核对授权。暂不做PI真实进程适配、离线双写、冲突合并、多Worker/DAG。
不承诺任意外部编辑器隔离、恶意TOCTOU、断电/旧备份混搭恢复、网络盘、无限历史保留。
文件与目录互换等结构性冲突首版明确拒绝，不删除未知目录来强行升级。

## 已知保守限制与后续使用

本轮没有服务器同版本复测、真实两台设备往返、完整Electron交互验收或真实PI进程适配。
上一轮56670320的真实单向结果不等于本轮实现已部署；原验收服务仍保持回收状态。
先保全本轮源码，之后只在明确授权的可丢弃工程上核对真实两端启用条件。

更新中断后原登记文件可能已部分变更，普通入口持续隐藏并拒写；
没有取消/回滚整个更新的公开命令。未知字节/inode或目录身份变化会保留现场并停止。
暂存失败残留保留，每文件最多16次；未做残留GC或完成收据保留期/清除策略。
更新收据project_id外键保留绑定，不支持据此宣称普通purge已适配。
旧程序/旧schema进程必须先退出，不能与新扩展并发混用；不直接升级真实业务库。
完整bundle仍只包含Forge登记范围，不保证整仓库、依赖、密钥或PI会话可用。
不要手工删除更新标记、改映射或复制旧备份拼接来“解除”拒写。
